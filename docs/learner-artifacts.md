# Learner artifacts

Issue #127 adds storage for outputs reused by later lessons and plans. It does not publish new lessons, add requirements to existing lessons, award rewards for outputs, or use learner-authored fees to execute Lab trades.

## Storage and contracts

`learner_artifact` holds one document per `(user_id, kind)` with append-only revisions. Each revision has its own UUID, positive monotonically increasing `version`, typed JSON payload, creation time, optional stable `source_lesson_id`, and a per-user request UUID. Current means highest revision number, not latest timestamp. No progress or reward migration is needed. Migration 0015 is additive; account deletion cascades through every revision. Deleting a source lesson only clears its attribution.

Payload contracts live in `src/features/artifacts/schemas.ts` and have exhaustive positive/negative tests. [The IPS builder](ips.md) extends `investment_plan` with an explicit v2 payload while continuing to read the original shape. Current kinds are `goal_map`, `financial_checkup`, `fee_profile`, `etf_checklist`, `safeguards`, `investment_plan`, `trade_checklist`, `business_map`, `investment_thesis`, and `journal`. The thesis and business map represent the current exercise; a journal is a bounded collection of entries. Separate concurrent documents of the same kind are not supported by this initial contract. `version` counts document edits, not schema versions: future incompatible payload changes require an explicit compatibility/migration plan.

Schemas reject extra fields, bound text/collections, validate calendar dates, and keep educational money as canonical integer minor-unit strings and rates as integer basis points. The check-up saves categories and a next step; it has no income, expense, account identifier, or debt amount fields. Goal maps save purpose, horizon and priority. The goals lesson also supports optional target years and exact educational target amounts in integer minor-unit strings; fictional data is allowed and no amount is required. An explicit no-specific-goal choice is represented by an empty goals array with `noSpecificGoal: true`. See [the goals lesson contract](education/lesson-reviews/goals-and-horizon.md). Free text should never request identifying or sensitive financial details.

## Server actions and consent

`saveArtifact({ content: { kind, payload }, sourceLessonId, consent: true, requestId })`, `listArtifacts({ kind? })`, and `deleteArtifact({ id })` derive the owner from the session. Inputs cannot specify an owner, revision, or creation time. Unknown sources and malformed payloads fail on the server. Actions return `{ ok: true, ... }` or a recoverable `{ ok: false, message }` without logging payloads or database errors. Listing returns current revisions, optionally filtered by kind; the account export includes all historical versions.

Every save requires an explicit consent value; lesson editors use `ArtifactSaveControl` to show an unchecked consent checkbox explaining reuse, history and deletion. It accepts typed content, a stable lesson ID (or `null` for an output created outside a lesson), and an optional saved callback. Keep editor drafts local until the learner chooses to save. Reuse the same request UUID while retrying the same input. Changed input needs a new UUID; reusing a UUID with different validated content is rejected.

Saves and deletes lock the same user row as lesson progression and account lifecycle operations. Concurrent saves allocate unique ordered revisions; concurrent retries create only one row. There is no update method. Deleting any owned revision removes **every version of that kind**. A foreign or already deleted ID is a harmless no-op, revealing no other learner's data. A later explicit save starts a new document at version 1.

Guests without a saved account cannot save, list, or delete artifacts, even with a valid anonymous guest session. Isolated demo identities can practice with artifacts; their normal deletion/cleanup removes all revisions. Guest claim behavior is unchanged because guests have no artifact rows to transfer.

## Lesson requirements

An authored `StepDefinition` may set `requiredArtifact: { kind: "goal_map" }`. By default, the current document must come from that same stable lesson ID. Explicit `source: "any_lesson"` permits reusing an output from another lesson. An editor and save control must be provided by the lesson that introduces a requirement; no existing published steps become gated here.

When moving forward, the progression transaction validates the current step's requirement against the owner's highest stored revision and its kind-specific schema. It never accepts a client presence flag. First completion rechecks **all** lesson requirements, including outputs deleted after passing a step. Both checks happen under the user lock, so they serialize with save/deletion. Missing or invalid outputs return a useful message through existing progress actions. Back navigation and lifetime completed-lesson reviews keep their existing behavior; deleting an output never revokes completion, changes timestamps, reissues receipts or relocks Lab.

## User controls and validation

Settings → Moje data lists current output names/revisions and lets the learner delete a complete history with inline confirmation. The existing account download exports every version with its payload, version, source and time. Owner and request keys are omitted. Account and anonymous cleanup use the existing user cascade.

Run `npm run lint`, `npm run typecheck`, `npm test`, and `npm run build`. `ARTIFACTS_QA_DISPOSABLE=1 npm run test:artifacts-persistence` requires an explicit local database named `investi_artifacts_qa`; it tests the migration chain and rerun, all kinds, concurrent versions/retries, owner isolation, guest rejection, export, deletion, requirement checks and lifetime progress/reward preservation. Run account-deletion and anonymous-cleanup integration tests only against a disposable database with their own opt-ins. `ARTIFACTS_QA_DISPOSABLE=1 npm run test:artifacts-browser` creates a temporary editor route and starts/stops its own dev server to test consent/retries and guest restrictions; it removes that route and its generated dev types afterward. To validate the shipped Settings deletion/export UI on a fresh production server, set `ARTIFACTS_TEST_URL` to its local URL. Both modes check keyboard focus, six responsive widths and 200% text.

## Optional public IPS summaries (#430)

A saved account can preview and explicitly publish a safe summary of a chosen `investment_plan` revision in Settings → Moje data. All other kinds, including the check-up, stay private. Budgets have no sharing path. Demo/guest identities cannot publish.

`artifact_share` (additive migration 0024) stores an unguessable access token, the immutable revision's ID and `projectionVersion: 1`, request ID, owner, creation and revocation time. It holds no payload copy. Later edits create new artifact rows and do not change the shared version. Projection v1 is frozen; broadening it requires a new version and explicit new consent. The allowlist uses only fixed labels for review frequency, rebalancing method and drawdown action (legacy IPS: frequency only). It never includes free text, names, money, income/expenses, reserve/debt readiness, goals, allocation, broker or instruments. Malformed and unsupported payloads fail closed.

Every mutation derives ownership from the current session and validates strict schemas. Create/revoke lock the same user row as artifact saves/deletion; per-user request IDs make retries and concurrent creates idempotent, and a retry cannot resurrect a revoked link. Source deletion cascades all grants; account deletion/anonymous cleanup use the existing cascade. Account export includes grant metadata, without public capability tokens or request IDs.

Public `/sdileni/[token]` and its `/obrazek` PNG endpoint read the same projection, every request. They are no-store/noindex and use no-referrer; revocation makes both return 404. Browsers/social platforms can retain already downloaded copies, and the consent copy explains that limit. The image uses the existing design tokens and Inter with its OFL license, with no external image/font requests. The public CTA creates no reward, and source counts use only `share:investment-plan`, never a unique token.

Use `GROWTH_QA_DISPOSABLE=1 npm run test:sharing-persistence` and `test:sharing-browser` only with local `investi_growth_qa`; the latter requires a fresh local production runtime, default port 3150, and can use `GROWTH_TEST_URL`. The browser test creates a disposable real account/session, tests preview and consent, secret exclusion in the HTML, PNG and download, old-revision isolation and page/image 404 after revocation. It also checks all requested widths, 200% text, keyboard, no-store/noindex and axe WCAG A/AA. The persistence suite checks additive migration/rerun, strict ownership, concurrent retries, every excluded artifact kind, fixed snapshots, revocation/retry, export and both deletion cascades. Normal development data is not reset or mutated.

## Module outputs (#457)

`cost_comparison` payload v1 stores the exact fictional Eva example in 2.2.5: 12 purchases of 250,000 CZK minor units, model EUR/CZK 24.30, both fictional tariff inputs and annual costs A 7,500 / B 48,240 minor units. Values are schema-validated, include order fees/FX/custody, and exclude fund TER and spread. Saving is optional in the existing final step, requires explicit consent, and grants no reward. It does not change any step, cursor, question, completion or receipt.

The ETF selection lesson's original `lesson_output` checklist remains authoritative. `asEtfChecklist` is a lossless read conversion for `etfs-selection-checklist` / block `checklist` only: it exposes the selected item IDs as `etf_checklist` payload v2 (`selection_checklist`), retaining revision ID, version, timestamp and source. It never turns selected intentions into verified UCITS/KID facts. Original exports and deletion use the original row; no backfill or duplicate is needed. Existing per-instrument ETF payloads remain readable. IPS and 2.5.3 can use the converted checklist.

IPS schema v2 adds optional `costComparisonId` and `etfChecklistId`. Each identifies an immutable owned revision, not a copied annual number or a mutable latest pointer. Older payloads need no rewrite. Save validates ownership and kind under the same owner lock; deletion leaves a historical reference unavailable and a new plan must remove/replace it. Stored plan history never changes. Artifact exports already include every raw revision; account deletion cascades all kinds. The final project shows a saved cost comparison as educational evidence only: rubric thresholds, automatic criteria and self-assessment are unchanged.
